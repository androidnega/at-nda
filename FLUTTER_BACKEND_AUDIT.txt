================================================================================
  PHASE 4 — PERFORMANCE AUDIT
================================================================================

F4.1  ⚠ rep_session_page.dart polls every 8 seconds AND calls multiple
      sequential HTTP endpoints per tick:
          1. ApiService.repCourses()
          2. _refreshClassActiveSessionAndStats()  (1–2 more requests)
      That is ~22 requests/minute per active rep. Combined with the
      Laravel side already optimised in commit `7076520a` (N+1 kill in
      ActiveSessionListBuilder, sargable index_number lookups), this
      is no longer a database hot-spot, but it still has three
      symptoms that ARE worth fixing in a follow-up PR (NOT done here
      because doing so changes user-visible behaviour, which the
      audit ruleset forbids):
        (a) `setState(() { _loading = true; })` on every tick produces
            a visible spinner flash every 8 seconds.
        (b) The timer keeps polling while the page is offscreen
            (Navigator stack push), the device is locked, or the app
            is backgrounded — there is no AppLifecycleState gate.
        (c) No `_inFlight` guard means an overlapping tick (slow
            network) will run a duplicate refresh in parallel.
      Suggested fix for a follow-up: gate with `_inFlight`, switch
      `setState({_loading=true})` to a quiet refresh (only set when no
      data yet), and pause the timer in `didChangeAppLifecycleState`.

F4.2  `home_page._load(silent: true)` is the right pattern — it only
      sets the loading flag when there is no cached data. Good design.

F4.3  FutureBuilder / StreamBuilder usage scan:
        - 0 `StreamBuilder<…>` for API data (all streams are UI-local
          ValueListenable / Notifier from `ThemeService` /
          `InstitutionThemeService`). ✓
        - `FutureBuilder` is used sparingly for small one-shots (chart
          building, profile-image precache). None of them re-fire on
          every rebuild because the futures are stored in
          `late final Future<…> _f = …()` fields. ✓

F4.4  Image loading:
        - `ProfileImageCache` already memoises the avatar bytes per URL
          with a TTL — good. Network avatars use `NetworkImage`’s
          built-in HTTP cache.
        - Big asset (`assets/images/auth/login-hero.jpg`) is loaded
          via `AssetImage` on the login screen only — fine.

F4.5  State management abuse:
        - No `Provider`/`Bloc`/`Riverpod` overuse — the project uses
          plain `StatefulWidget` + `ValueListenable` notifiers. Light
          and predictable.
        - `setState` is used on the same widget per network response,
          not on a parent that would rebuild children unnecessarily.

F4.6  Duplicate API requests:
        - On login, `LoginPage._handleLogin*` calls `login()` then
          immediately `loadAppSettings(forceRemote: true)` once.
        - `home_page._load()` calls `_syncClassRepFlagFromApi()`
          conditionally — only when login payload was incomplete; it
          short-circuits if rep flags are already present in the
          student model. No duplicates observed.

  PHASE 5 — SECURITY AUDIT
================================================================================

F5.1  ⚠ FIXED — 7 unguarded `print()` calls leaked in release builds.
      In release builds, `kReleaseMode` is true and `print()` still
      writes to the platform console (logcat / NSLog), which means
      these messages were visible to anyone with `adb logcat` or the
      iOS device log. The messages included response bodies, server
      URLs, and full stack traces. They have been wrapped in
      `if (kDebugMode) { … }` blocks. Concrete locations fixed:

        - lib/services/api_service.dart:655   (SESSION RESPONSE error)
        - lib/services/api_service.dart:675   (SERVER ERROR preview)
        - lib/services/api_service.dart:684   (INVALID RESPONSE preview)
        - lib/services/api_service.dart:697   (SESSION JSON PARSE ERROR)
        - lib/services/api_service.dart:714   (legacy sessions log)
        - lib/pages/home_page.dart:485        (SESSION ERROR)
        - lib/widgets/dynamic_widget_renderer.dart:33 (renderer failure)

F5.2  Token / password storage
      Mobile:
        - Sanctum bearer token  → `flutter_secure_storage` (Keychain on
          iOS, Keystore-backed `EncryptedSharedPreferences` on Android).
          ✓ correct usage in `OfflineService.setApiSessionToken`.
        - Session password (used by legacy `index_number + password`
          endpoints) → same secure storage.        ✓
        - bcrypt-style local password hash → kept in SQLite `students`
          table (NOT plaintext). ✓
      Web:
        - Both token and session password fall back to
          `SharedPreferences` → browser **localStorage**. localStorage
          is readable by any JS in the same origin, so a successful XSS
          would exfiltrate the bearer.
        - This is the standard Flutter Web compromise — `flutter_secure_storage`
          has no encrypted backend for the web. **Recommended (not
          applied in this audit):** add a strict
          `Content-Security-Policy` header in the Laravel response that
          serves the SPA assets and consider switching to short-lived
          tokens with a server-side refresh cookie for web builds.

F5.3  Logout cleanup (`OfflineService.clearCurrentStudent`) correctly:
        - calls `ApiService.logoutRemote()` to revoke the Sanctum token
        - removes the API password from secure storage / SharedPrefs
        - removes the API token from secure storage / SharedPrefs
        - clears the in-memory bearer
        - deletes the students/users rows in SQLite (mobile)
        - removes the SharedPrefs JSON (web)
      ✓ Complete.

F5.4  Hardcoded URLs / API keys / secrets
        - `lib/utils/constants.dart` line 7:
              `defaultValue: 'https://at-enda.manuelcode.info/api'`
          This is a HARDCODED PRODUCTION BASE URL. It is reachable in
          plain text in any release build (string can be grep’d from
          the IPA / APK). The user’s intention is clearly to override
          this with `--dart-define=API_BASE_URL=…` per environment, but
          builds without the override silently fall back to production.
          **Recommendation:** flip the default to an empty string and
          fail fast in `ApiService` if `baseUrl` is empty. Not
          applied here because doing so blocks any developer who runs
          `flutter run` without remembering the dart-define, which is a
          UX/build-workflow change the user should decide on.
        - `QR_SECRET` (line 57) correctly defaults to empty and is
          provided at compile time. ✓
        - No API keys or secret strings found anywhere else in
          `lib/`. ✓

F5.5  `lib/services/device_service.dart:16` calls
      `https://api.ipify.org`. This is an intentional public IP probe
      (used by `AttendanceFraudGuard` on the backend). No PII is sent.
      ✓ acceptable.

F5.6  `lib/services/api_service.dart` defines `localAuthOnly = false`
      and `debugShowSessionApiResponseOnHome = false` (constants.dart).
      Both are intentionally `false` in the committed code. ✓

Student model
-------------
  Flutter (lib/models/student.dart) parses:

  is a real concern because some legacy data is purely numeric).

Session model (raw map, no Dart class)
--------------------------------------

    id, course_id, course_code, course_title/course_name, week_id,

    all of the above except `requires_qr_proof` is computed at call site,
    and `already_marked` / `my_status` are appended by
    ActiveSessionListBuilder::buildRows. ✓ FULLY ALIGNED.

Attendance model (lib/models/attendance_record.dart)
----------------------------------------------------
  Flutter sends: session_id, course_id, week_id, index_number, lat, lng,
  qr_code (optional), face_descriptor (optional, native only), device_ip,
  device_id, timestamp.
  Laravel (AttendanceController@markAttendance) reads: session_id (or

Notification model
------------------
  Flutter parses `data.notifications[*]` with `id`, `title`, `body`.

Dashboard models
----------------

  payload directly with null-coalescing operators. This is a brittle
  but maintainable pattern; **no mismatches** were found during
  static review.

    This permits HTTP traffic — used for local development against
    Laravel via `http://10.0.2.2:8000/api`. **Hardening

    user to confirm whether HTTP is needed in any prod scenario):**
    add `android/app/src/main/res/xml/network_security_config.xml`
    that allows cleartext only for localhost/10.0.2.2 and reference it
    from the manifest (`android:networkSecurityConfig="@xml/network_security_config"`).

  ⚠ NSPhotoLibraryUsageDescription is NOT declared.

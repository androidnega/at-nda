BASE URL
--------
Use your Laravel backend URL. API routes are prefixed with /api

Example: https://your-domain.com/api

If using local dev: http://10.0.2.2:8000/api (Android emulator)
                    http://localhost:8000/api (iOS simulator)

================================================================================
API ENDPOINTS (All under /api prefix)
================================================================================

1. CHECK ONBOARDING
   GET /api/onboarding/check?index_number=BC/ITD/24/047

   Response:
   {
     "onboarded": true|false,
     "needs_face_enrollment": true|false,
     "student": null | { "id": 1, "index_number": "...", "first_name": "...", "last_name": "..." }
   }

   If student not found: onboarded=false, student=null

2. COMPLETE ONBOARDING
   POST /api/onboarding/complete
   Content-Type: application/json

   Body:
   {
     "index_number": "BC/ITD/24/047",
     "phone_number": "0244123456",
     "profile_image": "data:image/jpeg;base64,...",
     "face_descriptor": [0.1, -0.2, ...]  // 128 floats if face enabled
   }

2b. UPDATE PROFILE (after onboarding — syncs to web)
   POST /api/student/profile
   Content-Type: application/json

   Body (password required; other fields optional):
   {
     "index_number": "BC/ITD/24/047",
     "password": "your_password",
     "phone_number": "0244123456",
     "profile_image": "data:image/jpeg;base64,...",
     "first_name": "Jane",
     "last_name": "Doe"
   }

3. SAVE FACE (later)
   POST /api/onboarding/save-face
   Body: { "index_number": "...", "descriptor": [128 floats] }

4. GET STUDENTS
   GET /api/students
   GET /api/students?index_number=BC/ITD/24/047
   GET /api/students?class_id=1

   Returns JSON array with: index_number, name, profile_image, class, faculty,
   department, level, phone, has_password, face_descriptor (if enabled),
   bound_ip (if enabled)

4b. LOGIN (for sign-in with password)
   POST /api/login
   Content-Type: application/json
   Body: { "index_number": "BC/ITD/24/047", "password": "your_password" }

   Success 200: { "success": true, "student": { ... } }
   404: { "success": false, "message": "Index number not found" }
   401: { "success": false, "message": "Invalid password" }
   422: { "success": false, "message": "Password required" }
   422: { "success": false, "needs_set_password": true, "message": "Set password first via web" }

4c. LOOKUP STUDENT BY INDEX (for verification without password)
   POST /api/students/lookup
   Content-Type: application/json
   Body: { "index_number": "BC/ITD/24/047" }

   Or: GET /api/students/lookup?index_number=BC%2FITD%2F24%2F047
   (Use Uri.encodeComponent() for GET - slashes must be encoded as %2F)

   Response 200: { "found": true, "student": { ... } }
   Response 404: { "found": false, "student": null, "message": "Index number not found" }

   Use POST when possible - avoids URL encoding issues with slashes in index numbers.

5. GET FACULTIES (for profile/onboarding dropdowns)
   GET /api/faculties

   Returns: [ { "id": 1, "name": "Faculty of Engineering" }, ... ]
   Use for faculty dropdown. No duplicates.

6. GET DEPARTMENTS BY FACULTY
   GET /api/departments?faculty_id=1

   Returns: [ { "id": 3, "name": "Civil Engineering" }, ... ]
   Use for department dropdown after faculty is selected.

7. GET SETTINGS
   GET /api/settings

   Returns: face_verification, qr_code_enabled, ip_binding_enabled,
   require_password_on_first_login, allow_multiple_index, face_match_threshold

8. GET ACTIVE SESSIONS
   GET /api/sessions/active
   GET /api/sessions/active?index_number=BC/ITD/24/047
   GET /api/sessions/active?class_id=1
   GET /api/sessions/active?course_id=1&index_number=BC/ITD/24/047

   Returns JSON:
   { "sessions": [ { ... }, ... ] }
   Each object includes already_marked for that session (when index_number is sent).
   Use response["sessions"] — never a root-level "session" key.

9. SUBMIT ATTENDANCE
   POST /api/attendance
   Content-Type: application/json

   Body:
   {
     "index_number": "BC/ITD/24/047",
     "course_id": 1,
     "session_id": "abc123...",  // or qr_code - from QR payload
     "lat": 5.123,
     "lng": -1.234,
     "face_descriptor": [128 floats],  // if face verification enabled
     "timestamp": "2025-03-19T10:30:00.000Z"  // optional
   }

================================================================================
INDEX NUMBER FORMAT
================================================================================
Index numbers can include slashes: BC/ITD/24/047, BC/ITN/24/047, BC/ITS/24/047

Always send the index exactly as the student would enter it. The API trims
and uppercases for matching. Do NOT modify the format (e.g. replacing / with -).

================================================================================
FLUTTER IMPLEMENTATION CHECKLIST
================================================================================

1. Base URL
   - Store in config: final baseUrl = 'https://your-domain.com';
   - API calls: '$baseUrl/api/students', '$baseUrl/api/onboarding/check', etc.

2. HTTP Client
   - Use dio or http package
   - For POST: set headers: {'Content-Type': 'application/json'}
   - API routes do NOT require CSRF token (unlike web routes)

3. Onboarding flow
   - User enters index (e.g. BC/ITD/24/047)
   - Call GET /api/onboarding/check?index_number=BC/ITD/24/047
   - If onboarded=false: show onboarding form, then POST /api/onboarding/complete
   - If needs_face_enrollment: POST /api/onboarding/save-face

3b. Faculty/Department dropdowns (profile, onboarding)
   - Call GET /api/faculties for faculty list (no duplicates)
   - Call GET /api/departments?faculty_id=X when faculty selected

4. Fetch student (for login/verification)
   - PREFERRED: POST /api/students/lookup with body { "index_number": "BC/ITD/24/047" }
     Avoids URL encoding issues. Returns { "found": true, "student": {...} } or 404.
   - Or: GET /api/students?index_number=... (must URL-encode: Uri.encodeComponent(index))
   - If empty/404: student not found. Show "Index not found" or similar.

5. Fetch sessions
   - Call GET /api/sessions/active?index_number=BC/ITD/24/047
   - Parse json["sessions"] (list; may be empty). Each item has already_marked.

6. Submit attendance
   - POST /api/attendance with required fields
   - Check response: { "status": "success", "message": "..." }
   - On error: { "status": "error", "message": "Student not found" } etc.

================================================================================
COMMON ERRORS
================================================================================
- "Student not found" / "Index not found": Index not in database, wrong format, or
  URL encoding issue (slashes in GET params). Use POST /api/students/lookup instead.
- "Complete onboarding first": Call /api/onboarding/complete
- "Set password first": Student must set password via web
- "Out of range": Location too far from session
- "Face does not match": Face verification failed

================================================================================
WEB ROUTES (if mobile uses webview/session)
================================================================================
These require CSRF and session cookies:
- GET /onboarding/check
- POST /onboarding/complete
- POST /attendance/mark

Prefer API routes (/api/...) for mobile - no CSRF needed.

SECTION A — CANONICAL ATTENDANCE MODES TODAY
================================================================================

The `attendance_sessions.mode` column is a varchar (no DB CHECK constraint).
The app-layer-allowed values are enforced in TWO places:

  Site                                            Allowed values
  ----------------------------------------------  ------------------------
  ClassRepController::openInstantSession L.852    location | qr | hybrid | wifi | online
  FlutterSessionFormatter::format L.26 (REMAP)    qr | location | hybrid | wifi
                                                  (anything else, including
                                                   'online', is REMAPPED to 'qr'
                                                   before being returned to
                                                   Flutter — this is the
                                                   deliberate Flutter-
                                                   compatibility layer)

Semantic helpers on AttendanceSession (lines 333-361):

  requiresLocation()       -> mode in ('location','hybrid')
  requiresQrProof()        -> mode in ('qr','hybrid')
  isWifiMode()             -> mode === 'wifi'
  requiresWifiSsidProof()  -> isWifiMode()
  isCheckInCheckoutMode()  -> attendance_mode === 'checkin_checkout'
                              (different column — orthogonal to mode)

There is NO helper for `mode === 'online'` today. The current online flow
side-steps every helper above because `requiresLocation` / `requiresQrProof`
/ `isWifiMode` all return false when mode='online'.

The admin/portal session form (`admin/portal.blade.php` L.52-56) ONLY exposes
location/qr/hybrid — admin opening a session cannot pick wifi or online.

SECTION E — APIs (FLUTTER + WEB CONTRACT SURFACE)
================================================================================

E.1  /api/sessions/active (Flutter primary live-session feed)
       Controller : Api/SessionController::active L.20+
       Builder    : ActiveSessionListBuilder::isUsableActiveSession L.16
                    — mode-blind; online sessions ARE returned.
       Formatter  : FlutterSessionFormatter::format L.26 — REMAPS unknown
                    modes to 'qr'. Result: a Flutter client receiving an
                    online session sees mode='qr' and would try to scan a
                    QR that doesn't exist.
       Implication for new design:
         (a) Easiest: extend the FlutterSessionFormatter allow-list to
             include 'online' so Flutter sees the real mode and shows
             "open this session on the web" instead of pretending it's QR.
         (b) Safest for the deployed Flutter APK (which DOES NOT know
             'online'): leave the remap to 'qr' OR change to skip online
             sessions entirely in the active-list — students would still
             discover the session via web.

E.2  /api/attendance (Flutter mark)
       Already declines online sessions implicitly: it requires either
       qr_code (qr/hybrid) or location (location/hybrid) or wifi SSID
       (wifi). None of these match an online session, so the call would
       422 today. New design: same. Online stays web-only on submission.

E.3  /api/v1/sessions/active and /api/v1/auth/login
       Same shape via the same FlutterSessionFormatter — no extra work
       required beyond E.1's decision.

E.4  /api/attendance/{session}/export/(csv|excel|pdf)
       Mode-agnostic. No changes needed — online attendances render
       identically.

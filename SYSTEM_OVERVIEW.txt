1. SYSTEM OVERVIEW
================================================================================

The AT-NDA system is a Laravel-based attendance management platform for students.
It supports:

  • Web: Admin dashboard, Course Rep portal, Student login, Public attendance
  • Mobile: REST API for Flutter app (students, sessions, settings, attendance)
  • Multi-mode attendance: Location (GPS), QR code, or Hybrid

Flow:
  1. Admin creates courses, classes, sessions; uploads students; assigns course reps
  2. Course reps (or admin) open attendance sessions for their courses
  3. Students mark attendance via web or mobile (location, face, QR as configured)
  4. Admin exports attendance reports (PDF)

Tech: Laravel 11, PHP 8.x, MySQL, Blade templating, session-based auth.

2. USER ROLES & AUTHENTICATION
================================================================================

2.1 ADMIN
---------
  • Login: /admin/login
  • Session: admin_user_id or lecturer_id
  • Middleware: admin (EnsureAdminOrLecturer)
  • Can: Manage courses, classes, students, sessions, settings, venues, lecturers
  • Can: Import students, export PDF, reset student passwords

2.2 LECTURER
------------
  • Login: /lecturer/login
  • Session: lecturer_id
  • Middleware: admin (shares with admin)
  • Can: Same dashboard access as admin (configurable per implementation)

2.3 COURSE REP
--------------
  • Login: Same as student (index + password)
  • Session: student_id, student_index
  • Middleware: courserep (EnsureCourseRep)
  • Must be a student assigned as course rep for at least one course
  • Can: Open/close sessions, view QR, manage students in their courses
  • Can: Reset student passwords for their courses
  • Routes: /dashboard/reps/*

2.4 STUDENT
-----------
  • Login: /student/login (index + password)
  • Session: student_id, student_index
  • First-time: Redirected to set password if require_password_on_first_login
  • Can: View courses, mark attendance, view profile, update profile
  • Can: Use mobile app via API (no login required for API; index-only)

2.5 PUBLIC (No Login)
---------------------
  • Home: GET / — courses filtered by class (if filter set)
  • Filter by index: POST /filter-by-index
  • Attendance form: GET /attendance/{course}
  • Mark attendance: POST /attendance/mark (CSRF required)

3. DATABASE STRUCTURE
================================================================================

3.1 CORE TABLES
---------------

students
  id, index_number (unique), first_name, last_name, profile_image, phone_number,
  password, department_id, class_id, face_descriptor (json), bound_ip,
  created_at, updated_at

courses
  id, course_name, course_code, class_id, day_of_week, start_time, end_time,
  venue, lecturer_name, lecturer_id, venue_id, location_lat, location_lng,
  attendance_range_m, attendance_window_minutes, created_at, updated_at

classes
  id, name, code, faculty_id, department_id, level, created_at, updated_at

attendance_sessions
  id, course_id, attendance_week_id, mode, is_active, session_token,
  expires_at, location_lat, location_lng, attendance_range_m,
  created_at, updated_at
  mode: 'location' | 'qr' | 'hybrid'

attendance_weeks
  id, course_id, week_number, week_date, created_at, updated_at

attendances
  id, student_id, course_id, attendance_session_id, attendance_week_id,
  attendance_time, status, synced, created_at, updated_at
  status: 'present'

3.2 SUPPORTING TABLES
---------------------

course_reps
  id, student_id, course_id, role, created_at, updated_at
  Links students to courses they represent

universities
  id, name, location, created_at, updated_at

faculties
  id, name, university_id, created_at, updated_at

departments
  id, name, faculty_id, created_at, updated_at

system_settings
  id, enable_face_verification, enable_ip_binding, allow_multiple_index_on_device,
  enable_qr, require_password_on_first_login, face_match_threshold,
  created_at, updated_at

lecturers
  id, name, email, password, remember_token, created_at, updated_at

venues
  id, name, code, building, capacity, created_at, updated_at

users (Laravel default)
  id, name, email, password, remember_token, created_at, updated_at
  Used for admin login

3.3 SESSION TOKEN
-----------------
  attendance_sessions.session_token: 32-char random string for QR payload
  QR payload: { course_id, session_id (token), expires_at }

4. MODELS & RELATIONSHIPS
================================================================================

Student
  belongsTo: department, schoolClass (class_id)
  hasMany: courseReps, attendances
  belongsToMany: reppedCourses (via course_reps)

Course
  belongsTo: schoolClass, lecturer, venue
  hasMany: attendanceSessions, attendanceWeeks, attendances, courseReps

SchoolClass
  belongsTo: faculty, department
  hasMany: students, courses

AttendanceSession
  belongsTo: course, attendanceWeek
  hasMany: attendances

Attendance
  belongsTo: student, course, attendanceSession, attendanceWeek

CourseRep
  belongsTo: student, course

Faculty, Department, University
  Standard hierarchy: University -> Faculty -> Department

SystemSetting
  Singleton-style: SystemSetting::get() returns first/creates default

6. API ROUTES (MOBILE APP)
================================================================================

Base: /api (e.g. https://your-domain.com/api)

  GET  /api/students
    Query: index_number, class_id, course_id
    Returns: array of students with index_number, name, profile_image URL,
             class, faculty, department, level, phone, has_password,
             face_descriptor (if enabled), bound_ip (if enabled)

  GET  /api/sessions/active
    Query: course_id, index_number, class_id
    Returns: active session(s) for student's class
    Fields: course_id, course_code, course_title, week_id, lecturer_name,
           venue, location (lat/lng), range_meters, qr_enabled,
           face_verification_enabled, ip_binding_enabled, session_token, expires_at

  GET  /api/settings
    Returns: face_verification, qr_code_enabled, ip_binding_enabled,
             require_password_on_first_login, allow_multiple_index, face_match_threshold

  POST /api/attendance
    Body: index_number, course_id, session_id (or qr_code), lat, lng,
          face_descriptor (array), timestamp
    Validates: student exists, session active, location in range,
               face match (if enabled), QR (if enabled), IP binding (if enabled),
               password set (if require_password_on_first_login)
    Returns: { status: "success"|"error", message: "..." }

7. KEY USER FLOWS
================================================================================

7.1 STUDENT FIRST-TIME LOGIN (Web)
----------------------------------
  1. GET /student/login
  2. POST /student/check-index { index_number }
  3. If no password and require_password_on_first_login:
     -> Redirect to /student/set-password
  4. If no password and !require_password_on_first_login:
     -> Log in without password, redirect to dashboard
  5. If has password:
     -> Show password form, POST /student/login
  6. Session set -> redirect to /dashboard (student or course rep)

7.2 STUDENT ONBOARDING (Mobile/Web)
-----------------------------------
  1. GET /onboarding/check?index_number=X
  2. If !onboarded:
     POST /onboarding/complete { index_number, phone_number, profile_image (base64), face_descriptor }
  3. If needs_face_enrollment:
     POST /onboarding/save-face { index_number, descriptor }

7.3 ATTENDANCE MARKING (Web)
----------------------------
  1. GET / (filter by index if needed)
  2. Select course with available session
  3. GET /attendance/{course}
  4. Optional: POST /attendance/verify (pre-check)
  5. Optional: POST /attendance/verify-face (if face enabled)
  6. POST /attendance/mark { index_number, course_id, latitude, longitude, session_token? }
  7. Redirect to /attendance/{course}/success

7.4 ATTENDANCE MARKING (Mobile API)
-----------------------------------
  1. GET /api/settings
  2. GET /api/students?index_number=X (or cache)
  3. GET /api/sessions/active?index_number=X
  4. POST /api/attendance { index_number, course_id, lat, lng, session_id?, face_descriptor, timestamp }

7.5 COURSE REP OPEN SESSION
---------------------------
  1. Login as course rep
  2. GET /dashboard/reps (or dashboard)
  3. POST /dashboard/reps/sessions { course_id, ... }
  4. GET /dashboard/reps/sessions/{session}/qr — display QR for students

7.6 ADMIN IMPORT STUDENTS
-------------------------
  1. Login as admin
  2. GET /dashboard/students or /dashboard/classes/{class}
  3. POST /dashboard/students/import or /dashboard/classes/{class}/students/import
  4. CSV: index_number, first_name, last_name, (optional columns)

8. SYSTEM SETTINGS
================================================================================

Stored in system_settings table. Single row. Access via SystemSetting::get().

  enable_face_verification     bool   Require face match before attendance
  enable_ip_binding           bool   Lock student to device IP
  allow_multiple_index_on_device  bool   Allow multiple students per device
  enable_qr                   bool   Allow QR code attendance
  require_password_on_first_login  bool   Must set password before first use
  face_match_threshold        float  0.2–1.0 (lower = stricter)

Admin can toggle via /dashboard/settings.

Face match: Euclidean distance between 128-float descriptors. Verified if
  distance < face_match_threshold.

9. ATTENDANCE MODES & VALIDATION
================================================================================

9.1 SESSION MODES
----------------
  location: GPS only, no QR required
  qr:       QR required, location still checked
  hybrid:   QR or location

9.2 VALIDATION CHECKS (POST /api/attendance)
-------------------------------------------
  1. Student exists
  2. Student has password (if require_password_on_first_login)
  3. Student is onboarded (profile_image, phone, face if enabled)
  4. IP binding: device IP matches bound_ip (if enabled)
  5. Multiple index: no other student on same IP (if !allow_multiple)
  6. Session exists and is valid (is_active, !expired)
  7. Location: Haversine distance ≤ range_meters
  8. QR: session_token matches (if QR mode)
  9. Face: euclidean distance < threshold (if enabled)
  10. Time: within attendance_window_minutes

9.3 DISTANCE
-----------
  Haversine formula, Earth radius 6371000 m.
  distance(lat1, lng1, lat2, lng2) returns meters.
